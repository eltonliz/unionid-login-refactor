ACCOUNT IDENTITY FLOW

手机号先记临时访问，unionID 用于识别项目用户

手机号 + 验证码通过后只写临时访问记录。取得 unionID 后，系统按手机号开关和身份结果决定是否创建用户或登录；确认的手机号不一致时不覆盖、不重复建号。

01 / 仅手机号写临时访问记录
02 / 取得 unionID按开关创建或登录
03 / 本人验证同号进入项目内合并判断
04 / 号码不一致保留账号等待一致
用户生成口径

正式用户必须有 unionID。若微信登录开关要求手机号，新用户还须先完成手机号验证；拒绝授权不创建新用户，已有账号及数据不受影响。

01 / TENANT POLICY

开关只控制微信登录时是否必须绑定手机号

开关不影响手机号验证码登录；账号只在当前租户、当前项目内查找和处理。

微信登录是否强制绑定手机号

关闭：微信身份确认成功即可登录，手机号可后续补充。

当前规则：关闭取得 unionID 后处理登录

微信授权成功后先判断 unionID；手机号只在后续手机号触点或用户授权验证后参与匹配。

从关闭改为开启

开关只影响切换后的微信登录：新登录按“必须绑定手机号”执行。历史收货地址、通讯录等业务号码不自动批量合并；本期不扫描历史号码；已有候选保持原状态。

02 / USER CREATION

手机号临时访问和正式用户创建分开处理

手机号验证只解决临时访问；unionID 是创建正式用户的必要条件，开关开启时还须先完成手机号验证。

账号范围

所有账号都是项目级账号。临时记录、正式用户、合并候选和资产处理均限定 tenant_id + project_id。

PROJECT SCOPE
01 / 手机号验证码只写临时记录

保存手机号、端、项目、验证方式和时间；不创建正式用户。

02 / 临时访问仅允许看首页

未取得 unionID 时，不开放六类关键事件。

03 / 六类关键事件触发微信授权

进入直播、下单、立即购买、收藏、分享、我的时必须授权。

04 / 拒绝必要授权终止本次登录

新用户不创建；已有账号不删除或改动。

05 / unionID 和开关完成身份判断

关闭开关可按 unionID 登录/建号；开启时新用户先验证手机号。

06 / 后续号码碰撞本人验证后再判断

同号进入待处理合并判断；本期只记待处理候选，原账号和资产不变。

04 / PHONE MATCH TRIGGERS

手机号碰撞入口分开处理

业务手机号只生成待确认候选；必须再通过微信手机号授权或短信验证，才能作为合并依据。

01 / 首次下单填写收货地址手机号

收货号码碰撞时生成候选；订单照常按原流程提交，地址号码不能直接当作账号本人凭证。

02 / 通讯录被邀请或填写手机号

邀请号码碰撞时生成候选；通讯录不是六类强制微信授权事件，邀请流程不因合并判断失败而中断。

本期不包含手机号换绑

当前 APP 没有个人中心修改手机号入口，本期无此流程。

手机号确认后的处理

用微信手机号授权或短信验证得到号码后重新匹配当前项目：验证同号且命中当前项目两个账号时，只记录待处理候选；异号、拒绝或验证失败时保留账号独立。两边资产均不迁移。

05 / IDENTITY RESOLVER

先判断有没有 unionID，再处理手机号记录

手机号临时记录不是正式用户，不能再用“手机号命中账号”作为第一层判断。

处理结果

只保留临时访问记录

没有 unionID，不创建 user；仅可查看首页，关键事件必须先完成微信授权。

06 / DECISION ORDER

正式用户生成和合并按六步判断

手机号验证通过不等于创建用户；必须等 unionID 到达后才能进入用户判断。

01 / 确定范围锁定当前租户和项目

临时记录、用户查找、候选匹配和合并都带 tenant_id + project_id。

02 / 手机号临时记录不写 user

保存手机号、端、项目、验证方式和时间，只提供首页临时访问。

03 / 微信授权与开关按 unionID 查找，按开关决定建号时点

unionID 命中则进入原用户；未命中时，若开关开启先验证手机号再建用户，否则直接建号。openID 只能与 AppID 组合。

04 / 手机号候选匹配业务号码先发现，再授权确认

收货地址、通讯录号码可触发碰撞；本人须通过微信手机号授权或短信验证。

05 / 双账号判断同号记候选，异号继续等待

确认号码一致后进入当前项目合并判断；本期只记录待处理候选，原账号及资产不变。

06 / 完成或退出满足规则后继续，拒绝则退出

新用户拒绝必要授权时不建号；已有用户保留。创建与候选处理必须幂等并留记录。

两种登录方式 × 两个端 × 两种开关状态

8 种组合都列明适用状态和开关影响，不把“不适用”误写成一条待实现链路。

08 / LOGICAL RECORDS

三类记录分别承担临时访问、正式用户和待处理候选

只展示本期需要的三类记录；账号合并完成态不在本期范围。

01 / 临时记录phone_visit_record

手机号验证码成功但尚无正式用户时写入。

  • tenant_id、project_id
  • phone、verify_type、verify_status
  • terminal、AppID、visit_time
  • unionID：授权后关联（如已取得）
02 / 正式用户project_user

按 unionID 在当前项目创建或命中，承载项目身份。

  • user_id、tenant_id、project_id
  • unionID、AppID + openID
  • verified_phone（经本人验证）
  • status、created_at
03 / 待处理候选user_merge_candidate

号码碰撞或双账号判断时记录候选；另一侧可为正式账号，也可为临时访问记录。

  • 触发入口、项目、号码验证结果
  • 关联账号或临时记录（可为空）
  • 待验证 / 待处理 / 不合并
  • 验证结果、触发来源和时间
