用户生成口径

没有 unionID 就没有正式用户。用户拒绝关键事件中的微信授权时，本次流程终止并退出；临时访问记录保留，但 user 表不产生用户。

01 / TENANT POLICY

开关只控制微信登录是否立即要求手机号

无论开关状态如何，正式用户都必须由 unionID 创建或识别；项目范围仍按此前负责人确认执行。

微信登录是否强制绑定手机号

关闭：先用 unionID 创建或进入正式用户，手机号在后续触点补充。

从关闭改为开启

系统立即检查当前项目已保存的手机号记录：可信手机号可进入匹配；收货地址、通讯录、手填号码只生成待确认候选，用户下次进入或操作时仍需微信手机号授权或短信验证。

当前规则：关闭unionID 先建用户，手机号后补

微信授权成功即可创建或进入正式用户；修改手机号、下单地址或通讯录等触点出现同号时，再触发手机号确认和合并判断。

02 / USER CREATION

手机号注册和正式用户创建分成两步

手机号验证只解决临时访问；unionID 才是创建正式用户的必要条件。

项目边界依据

“所有账号都是项目级”来自负责人后续单独确认，并非会议纪要推导。临时记录、正式用户、合并候选和资产处理均限定 tenant_id + project_id。

CONFIRMED ADDITION
01 / 手机号验证只写临时记录

保存手机号、端、项目、时间和验证结果；user 表不创建用户。

02 / 临时访问仅允许看首页

没有 unionID，不开放需要正式身份的业务能力。

03 / 关键事件触发微信授权

进入直播、下单、立即购买、收藏、分享、我的时必须授权。

04 / 拒绝授权终止并退出

不产生正式用户，不保留正式登录态；临时访问记录用于追踪。

05 / 取得 unionID创建或找到正式用户

跨 APP、小程序使用 unionID；openID 必须结合 AppID。

06 / 匹配与合并补手机号或进入合并

匹配相同号码后完成授权确认；两个用户满足条件才合并当前项目数据。

04 / PHONE MATCH TRIGGERS

开关关闭时，这些手机号动作会触发匹配

业务手机号只负责发现可能是同一个人，不能静默成为账号凭证。

01 / 个人中心修改手机号

新号码与临时记录或正式用户号码相同，生成合并候选并要求确认号码。

02 / 首次下单填写收货地址手机号

号码发生碰撞时触发匹配；收货人号码本身不直接证明是账号本人。

03 / 通讯录被邀请或填写手机号

相同号码生成候选；通讯录不是六类强制微信授权事件。

待负责人确认的折中规则

业务手机号命中相同号码后，弹出微信手机号授权或短信验证，可展示可选号码列表并允许多次选择。用户确认到相同号码才合并；选择 137 等其他号码时保留两个用户，后续再次出现 138 时重新判断。

05 / IDENTITY RESOLVER

先判断有没有 unionID，再处理手机号记录

手机号临时记录不是正式用户，不能再用“手机号命中账号”作为第一层判断。

处理结果

只保留临时访问记录

没有 unionID，不创建 user；仅允许查看首页，关键事件必须先完成微信授权。

06 / DECISION ORDER

正式用户生成和合并按六步判断

手机号验证通过不等于创建用户；必须等 unionID 到达后才能进入用户判断。

01 / 确定范围锁定当前租户和项目

临时记录、用户查找、候选匹配和合并都带 tenant_id + project_id；这是负责人补充确认规则。

02 / 手机号临时记录不写 user

保存手机号、端、项目、验证方式和时间，只提供首页临时访问。

03 / 微信授权取得 unionID 后才建用户

unionID 命中则进入原用户；未命中则创建正式用户。openID 只能与 AppID 组合使用。

04 / 手机号候选匹配业务号码先发现，再授权确认

修改手机号、收货地址、通讯录号码可触发碰撞；微信手机号或短信验证完成本人确认。

05 / 双用户判断一致合并，不一致等待

确认号码一致才进入当前项目合并；选择其他号码时两条记录进入等待合并状态。

06 / 完成或退出成功返回原操作，拒绝则退出

拒绝微信授权不创建用户；创建、匹配和合并都必须幂等并保留审计。

08 / LOGICAL RECORDS

三类记录分别承担临时访问、正式用户和等待合并

这里是产品逻辑结构，不是最终 SQL DDL；字段名可由架构师按现有表调整。

01 / 临时记录phone_visit_record

手机号验证成功但还没有 unionID 时写入。

  • tenant_id、project_id
  • phone、verify_type、verify_status
  • terminal、AppID、visit_time
  • union_status：未授权 / 已授权
02 / 正式用户project_user

取得 unionID 后创建或命中，承载当前项目身份和资产。

  • user_id、tenant_id、project_id
  • unionID、AppID + openID
  • verified_phone
  • status、created_at
03 / 合并候选与记录user_merge_candidate

两条记录暂不合并、等待手机号一致或授权确认时写入。

  • source_user_id、target_user_id
  • candidate_phone、trigger_source
  • verify_status、merge_status
  • created_at、merged_at、result
