UNIONID ACCOUNT RESOLUTION

把“登录方式”与“业务账号”分开

系统始终登录内部 user_id。UnionID、OpenID 和手机号都是找到 user 的已验证凭证，不是业务数据主键。

一条总规则UnionID 与手机号指向同一用户则登录；只命中一边则补绑；分别命中两个用户则立即停止，进入账号冲突。
01 / FOUNDATION

四个概念，不能混用

先统一身份定义，再讨论登录与合并。

口径已固化
ACCOUNT_ID

内部业务账号

订单、会员、收藏、余额和权益的真正归属。永久不用外部凭证替代。

WECHAT_UNION

UnionID

同一微信开放平台账号范围内的跨 AppID 微信身份，用于 APP 与小程序识别。

WECHAT_CHANNEL

AppID + OpenID

单一应用渠道内的微信身份。OpenID 必须连同 AppID 保存，不做跨端兜底比较。

VERIFIED_PHONE

已验证手机号

登录与联系凭证，可能换号、共用或被回收，不能覆盖已存在的 UnionID 归属。

数据隔离原则

可在平台层识别同一个 account，但每个租户必须建立独立 tenant_user。不得因 UnionID 相同跨租户带出订单、角色、通讯录和会员权益。

02 / TENANT POLICY

租户配置：微信登录是否强制绑定手机号

开关只控制微信登录时的手机号要求，不改变手机号本身的登录能力。

当前：关闭

强制绑定手机号

适用 APP 微信登录和小程序微信登录。获取手机号前仍需用户明确同意。

开关不建议命名为“是否允许获取手机号”，因为“允许”是能力范围，“强制”是流程门槛，两者含义不同。
OPTIONAL

允许 UnionID-only 用户

用户微信登录后可直接进入系统，不在登录阶段索取手机号。

  • 新用户创建 WECHAT_ONLY 账号
  • 存量用户不追溯补绑
  • 关闭后不删除已有手机号
03 / LOGIN FLOWS

两条登录主流程

先校验凭证，再解析业务账号；登录顺序不能改变最终结果。

顺序无关
STEP 01

校验微信凭证

APP 校验 OAuth code；小程序校验 wx.login code。

STEP 02

获取 UnionID

同时保存渠道级 appid + openid，不用 OpenID 做跨端判断。

STEP 03

查询身份归属

先查 UnionID；若需手机号，再独立查询手机号归属。

STEP 04

执行决策矩阵

创建、补绑、登录或冲突。不得按先后顺序写分支。

STEP 05

签发业务会话

对最终 account_id 签发会话，再加载当前 tenant_user。

当前开关关闭：UnionID 验证成功后可完成登录。WECHAT_ONLY 可用
STEP 01

验证手机号

验证码通过后查询或创建 PHONE_ONLY 账号。

STEP 02

用户触发绑定

在账号中心或确有跨端同步价值的场景发起，不一刀切拦截。

STEP 03

获取 UnionID

用户取消时保留原手机号会话，不新建用户。

STEP 04

检查 UnionID 归属

未占用则绑定当前用户；已属于当前用户则幂等成功。

STEP 05

其他用户已占用

停止绑定，进入 IDENTITY_CONFLICT，不静默切换账号。

授权成功后保留原始 intent，回到用户刚才的操作。拒绝不登出

    05 / EDGE CASES

    三个极端 CASE 的正确口径

    不用“反之也是”写逻辑；无论先 APP 还是先小程序，同一组凭证都得到同一结果。

    双手机号重点

    已有状态

    APPPHONE_ONLY
    手机号139****0139
    UnionID未绑定
    小程序号码也是 139，且 UnionID 未占用时，才可将 UnionID 绑定到原用户。

    处理规则

    1. 先查 UnionID 是否已属于其他用户。
    2. 手机号相同只是绑定候选，需确保本次凭证有效。
    3. 若手机号不同且 UnionID 无历史，无法证明是同一人，可作为独立用户。
    4. 若 UnionID 已属于其他账号，不得自动合并。

    已有状态

    APPACTIVE_BOUND
    UnionIDU-1024
    手机号138****0138
    小程序取得同一 U-1024 时，已确定是同一微信身份；手机号不同不能再创建用户。

    处理规则

    1. UnionID 相同：登录已有用户。
    2. 新手机号未占用：进入换号或新号码确认，不自动覆盖。
    3. 新手机号已属于其他用户：进入 IDENTITY_CONFLICT。
    4. 禁止“手机号≠138就新建用户”。

    已有状态

    小程序WECHAT_ONLY
    UnionIDU-2048
    手机号未采集
    APP 手机号用户后续绑微信时，比较新取得的 UnionID，不比较 APP 与小程序 OpenID。

    处理规则

    1. UnionID 相同：是同一微信身份。
    2. 若两端已形成两个 user_id，进入账号归一或冲突流程。
    3. UnionID 不同：不自动合并。
    4. 无 UnionID：暂时无法跨端判断，不得退化为比较 OpenID。
    06 / TRIGGER POLICY

    关键事件不应一刀切强制微信授权

    用户已通过手机号登录，除非动作本身依赖微信身份，否则不应为了补数据而中断操作。

    需修正原需求
    事件是否依赖微信身份推荐处理用户拒绝后
    观看直播通常不依赖直接进入；互动、领权益时按具体业务校验不影响观看
    收藏不依赖，手机号账号已可记录先完成收藏；可在账号中心提示绑微信保留收藏结果
    分享分享 SDK 不等于微信登录不强制 OAuth；如有分享奖励再单独规定仍可分享
    通讯录依赖手机系统通讯录权限走系统权限流程，与微信身份授权分开展示手动搜索/添加方案
    我的不依赖，已有登录态展示绑定入口，说明“用于跨端同步”仍可访问我的
    立即购买购买依赖业务账号，不必然依赖微信身份使用当前账号下单；联系号码按订单规则校验不应因拒绝绑微信阻断下单
    推荐的一次性绑定触发点：账号中心主动绑定、用户主动开启跨端同步，或从 APP 跳转小程序前明确告知。不把六个普通入口全部变成强制拦截点。

    08 / DELIVERY CONTRACT

    研发实现契约

    前端只展示状态和收集授权；最终身份归属必须由后端在事务中决定。

    可交研发

    最小数据模型

    • account：平台内部业务账号。
    • auth_identity：PHONE、WECHAT_UNION、WECHAT_CHANNEL 与 account 的绑定。
    • tenant_user：租户内资料、角色和业务数据。
    • merge_record：冲突、验证、合并和回滚审计。

    服务端强约束

    • 对开放平台命名空间 + UnionID 建唯一约束。
    • 对 appid + openid 建唯一约束。
    • 身份查询、创建、绑定在同一事务内完成。
    • 每次授权流程使用 auth_flow_id 幂等，防止并发重复建号。
    resolveIdentity(openPlatformId, unionId, verifiedPhone, tenantId) {
  unionAccount = findByUnion(openPlatformId, unionId)
  phoneAccount = findByPhone(verifiedPhone)

  if (!unionAccount && !phoneAccount) return CREATE_ONE_ACCOUNT
  if ( unionAccount && !phoneAccount) return LOGIN_AND_CONFIRM_PHONE
  if (!unionAccount &&  phoneAccount) return BIND_UNION_AND_LOGIN
  if (unionAccount.id === phoneAccount.id) return LOGIN_EXISTING
  return IDENTITY_CONFLICT
}
    “合并账号”不等于批量改历史表的 user_id。有资产账号建议保留原始记录，通过 canonical account / merged alias 统一未来登录入口。
    09 / ACCEPTANCE

    必须通过的验收场景

    测试不只看能不能登录，还要验证账号归属、历史数据与异常状态。

    8 类用例
    1
    顺序无关同一组凭证先 APP 或先小程序，最终归属一致。
    2
    同 UnionID 异手机号不新建用户，进入换号或手机号冲突。
    3
    同手机号异 UnionID已有微信归属冲突时不覆盖、不自动合并。
    4
    两个已有账号进入 IDENTITY_CONFLICT，不产生第三个账号。
    5
    拒绝授权保留原会话，不建号、不半绑定、不丢失原操作状态。
    6
    重复/并发授权多次回调幂等，不重复创建用户或发放权益。
    7
    租户隔离同 UnionID 不能跨 tenant_id 带出订单、角色和通讯录。
    8
    开关变更从关到开有明确的存量补绑节点；从开到关不删历史手机号。
    用于业务评审·非生产系统口径基线：2026-09-24
    IDENTITY_CONFLICT

    发现两个已有账号

    UnionID 已属于用户 A，当前手机号已属于用户 B。系统不会自动覆盖、新建第三个用户或迁移资产。
